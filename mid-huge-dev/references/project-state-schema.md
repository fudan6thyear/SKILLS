# PROJECT_STATE.md Schema

`docs/pm/PROJECT_STATE.md` is the dashboard. It is written **only** by the orchestrator (PM role).
Every command that changes a card updates it in the same turn — a stale state file is worse than no
state file, because the next session will trust it.

Generated by `scripts/init-project.sh`; kept current by hand after that. Sections are ordered by how
often they're read.

## Update rules

| Event | Sections to touch |
|---|---|
| Card created | 待办任务, 任务统计 |
| Card dispatched | 待办 → 进行中, 任务统计 |
| Report accepted | 进行中 → 已完成, 任务统计; 契约变更记录 if any |
| Report rejected | Card stays in 进行中; append the rejection reason to 当前阶段说明 |
| Card blocked | 进行中 → 受阻, add to 阻塞问题 |
| Blocker resolved | 阻塞问题 status → 已解除; card back to 进行中 or 待办 |
| Contract change | 契约变更记录 + enumerate dependent cards |
| User makes a call | 决策日志 |

## Rules of thumb

- **Counts must reconcile**: 已完成 + 进行中 + 待开始 + 受阻 = total cards on disk. If not, the
  state file is lying — fix it before doing anything else.
- **阻塞问题 always names the decision needed**, phrased as a choice. "请指示" and "需要支持" are
  not decisions and will sit unresolved.
- **契约变更 with an empty 影响评估 is a red flag** — it usually means nobody checked.
- Never delete history from 已完成任务 or 决策日志; append. The value of the file is that it only
  grows.
