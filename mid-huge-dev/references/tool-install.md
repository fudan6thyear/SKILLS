# Installing across tools

One source of truth, three tools. `scripts/install.sh` is idempotent and never overwrites a file it
didn't create.

```bash
bash scripts/install.sh            # install / refresh
bash scripts/install.sh --check    # report only
```

## Per-tool resolution

| | Claude Code | opencode | Codex |
|---|---|---|---|
| **Skill root** | `~/.claude/skills/` | `~/.claude/skills/` + `~/.agents/skills/` | `~/.codex/skills/` + `~/.agents/skills/` |
| **How it's installed here** | native (this directory) | scanned directly — nothing to install | symlink `~/.codex/skills/mid-huge-dev` |
| **Agents root** | `~/.claude/agents/` | `~/.config/opencode/agent/` | none |
| **How roles are installed here** | native, untouched | 4 generated wrappers | read `references/roles/*.md` at dispatch |

Both opencode and Codex also scan `~/.agents/skills/`, so that symlink alone covers them — the
`~/.codex/skills` link is explicit rather than load-bearing. Verified with
`opencode debug skill` (reports `location: ~/.agents/skills/mid-huge-dev/SKILL.md`).

## Why the roles are duplicated instead of symlinked

`~/.claude/agents/*.md` carry Claude-specific frontmatter:

```yaml
model: opus
tools: [Read, Write, Edit, Bash, WebSearch]
```

opencode's agent schema wants `mode: subagent` plus a tool map, and derives the agent's name from
the filename rather than the YAML. Codex has no agent registry at all. A single file can't satisfy
all three without carrying keys each tool would either reject or silently ignore.

So the split is:

- **Canonical**: `~/.claude/agents/*.md` — edit these.
- **Portable**: `references/roles/*.md` — generated by `scripts/sync-roles.sh`, frontmatter stripped,
  tool-neutral prose.
- **Wrappers**: `~/.config/opencode/agent/*.md` — generated by `install.sh`, small, always pointing
  at the portable file rather than copying it, so a role edit can't go stale in opencode.

After editing an agent:

```bash
bash scripts/sync-roles.sh    # regenerate references/roles/
bash scripts/install.sh       # refresh wrappers if the role list changed
```

## Codex specifics

There is no named-subagent registry. `agents.toml`, `default_subagent_model`, `max_depth`, and
`max_concurrent_threads_per_session` under `[features.multi_agent_v2]` control the *budget*, not
roles. So role specialization travels in the prompt: read `references/roles/<role>.md` and inline it.

`agents/openai.yaml` sets `allow_implicit_invocation: false` — the workflow is heavyweight and
should trigger on explicit `$mid-huge-dev`, not on ordinary "build me an app" requests.

## Verifying after install

```bash
opencode agent list                     # expect: pm/architect/backend/qa-agent, all (subagent)
opencode debug skill                    # expect: mid-huge-dev at ~/.agents/skills/...
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py ~/.codex/skills/mid-huge-dev
```

Claude Code picks the skill up in the next session. opencode loads config once at startup and does
not hot-reload — restart it. Codex rescans skills on start.

## Caveats

- **Symlinks**: `~/.codex/skills/mid-huge-dev` points at the Claude skills tree. If you ever move or
  delete `~/.claude/skills/mid-huge-dev`, re-run `install.sh` from the new location. Codex has an
  `allow_symlinked_codex_homes` setting for the *codex home* itself; a symlinked skill directory
  inside it works normally.
- **Path hardcoding**: the generated opencode wrappers embed an absolute path to
  `references/roles/`. Re-run `install.sh` if you relocate the skill.
- **Deleting the skill**: remove the two symlinks and the four wrapper files by hand.
  `install.sh` never deletes.
